Free Next.js + Supabase + Stripe security checker

Your AI agent shipped the app. Did it also ship a Stripe secret key, a table without RLS or an open webhook? This free CLI runs 24 checks locally. No account, no uploads.

Honest limits

  • Heuristic static scan, 24 checks. A clean run isn't proof of security.
  • False positives happen: it doesn't follow data across files (for example, auth in a helper it doesn't recognise).
  • Not checked: your live Supabase project, dashboard policies, Stripe settings, dependencies, full git history.

View on GitHub

Run it once

Node 18+ and git. It isn't on npm yet, so npx runs it straight from GitHub:

npx github:edtrackai/nextjs-supabase-stripe-security-checker /path/to/your/app

Interactive runs print a one-line ad for our paid tools (off with --quiet; never in CI or --json).

Or clone it and try it on the included vulnerable sample app first:

git clone https://github.com/edtrackai/nextjs-supabase-stripe-security-checker.git
cd nextjs-supabase-stripe-security-checker && npm install
node bin/nss-security-check.js fixtures/vulnerable-app
node bin/nss-security-check.js /path/to/your/app --fail-on=high

Run it on every pull request

- uses: edtrackai/nextjs-supabase-stripe-security-checker@v0
  with:
    fail-on: high

The Action writes a job summary, adds file/line annotations and keeps one PR comment up to date. It needs contents: read, plus pull-requests: write only for the comment. Inputs: path, fail-on (critical | high | medium | low | none), comment, github-token. Full workflow: docs/github-action.md.

What it checks

Leaked keys (K1–K4), server auth (A1–A5), Supabase RLS and Data API grants (R1–R6), Stripe webhooks and checkout (S1–S7), and hardening (H1–H2). The full list with severities is in the README.
