Honest limits

  • Rules are pattern-based. Rephrased or encoded commands can get past them.
  • On Node older than 20.16, and in the Claude Code mod, the guard can't read files on disk: commands hidden in package.json scripts behind npm run are not expanded, and Edit checks look at the new text only.
  • curl/wget/netrc config files are matched by literal name. Globs (~/.n?trc), quote-splitting (~/.ne""trc), a path built in a variable, a proxy or XDG_CONFIG_HOME set outside the command, or a file written outside the agent get past that check.
  • A config file written by a script (for example Python) and copied into another folder, then used through HOME= or a symlink, gets past the config-file check. Since 1.1.1, a curl/wget call to an official host that sets HOME= (or XDG_CONFIG_HOME=, CURL_HOME=) in the same command loses its exemption, so that last step is denied when HOME= is in the command itself (tested). HOME set outside the command, or a symlink, is not seen.
  • Commands run as another user (sudo -u <user> ..., su <user> -c ...) read that user's ~/.curlrc, ~/.netrc and ~/.wgetrc, so the config-file and HOME= checks don't apply to them.
  • Symlinks or hard links to these files are not matched.
  • MCP file tools (for example a filesystem MCP server) are not checked for those config files, and Cursor agent edits to them are not denied (no pre-write hook).
  • Codex: hooks you haven't trusted in Codex's /hooks, or that changed since you trusted them, are skipped silently. Run the included check script after installing or updating.
  • Codex: there is no fail-on-error setting; the wrapper is what makes the hooks fail closed.
  • Codex: OpenAI describes hooks as "a useful guardrail, not a complete enforcement boundary".
  • Codex: async hooks can't deny a call, and hosted tools (run by OpenAI, such as web search) aren't hooked.
  • Codex: don't assume Codex cloud tasks enforce these hooks. The Codex IDE extension shares the config but is untested.
  • Codex: the optional rules match command prefixes only (FOO=1 supabase db push gets past the rules; the hook denies it).
  • git commit --no-verify and git push --no-verify skip the git hooks.
  • Not included: runtime or production monitoring, a scan of your existing code (that's Launch Audit), coding skills and rules (that's Ship-Ready AI Rules).
  • Not tested: a live Claude Code or Cursor session, a live OpenAI model with Codex, the Codex IDE extension, Codex cloud tasks, live Supabase or Stripe accounts, Windows.
  • No guarantee. A clean result is not proof the app is secure.
