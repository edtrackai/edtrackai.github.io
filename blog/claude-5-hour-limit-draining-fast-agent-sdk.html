Claude 5 hour limit draining fast in T3 Code or Agent SDK

Your Claude 5-hour limit runs out far sooner than usual when you work in T3 Code, an app built on the Claude Agent SDK, or headless claude -p, even though the same kind of work in the Claude Code terminal app lasts much longer. As of October 2026, several users have measured this in public, but Anthropic hasn’t confirmed it or announced a fix. This guide, updated 31 Oct 2026, covers what the user reports show and what you can do while the report is open.

If you want the next step, read Claude Code usage limits: how to reduce token usage so they last (Pro and Max).

Quick answer

  • It’s a user-reported metering gap, not a confirmed Anthropic bug. Users measure the same tokens using more of the 5-hour window through the Agent SDK and claude -p than through the interactive Claude Code app.
  • For heavy work, the interactive Claude Code app is the path users measured as cheaper on the 5-hour window.
  • Check your real usage with /usage in Claude Code before you change anything.
  • If you’re on Max, Ultra or Team, Anthropic’s monthly API credits cover Agent SDK and claude -p runs that use a Console API key. See Step 3.
  • Anthropic said on 30 Oct 2026 that it is removing the 5-hour limit for verified Ultra accounts, starting with most existing subscribers. This guide is about the plans and accounts that still have one.
  • Add your numbers to the open GitHub issue, so Anthropic sees more than one data point.

What users report

The main report is anthropics/claude-code#97074, opened on 25 Sep 2026 and still open. On a Max plan, its author says the same workload “uses about 1.8× more of the 5-hour window when it runs headless” (claude -p, recorded as sdk-cli) than in the interactive app, with the same token usage. As of 31 Oct 2026, the issue has more than 120 +1 reactions and 60 comments from 38 accounts, the author included. Besides the author, at least 12 commenters posted their own measurements or comparison data, including on Pro, Max and Team plans. The ratios they report range from about 1.3× to about 3×, from different methods and baselines, so the size of the gap is still uncertain. None of the 60 comments is from an Anthropic account that we could identify, and Anthropic hasn’t said whether the difference is a bug or intended.

On 24 Oct 2026, DeepakNess posted on X that after downloading T3 Code, one session on Claude Max “emptied the whole 5-hour limit in ~30 mins”. T3 Code’s maker, Theo, then posted: “I confirmed it’s a real bug on Anthropic’s side. To be clear: this does not affect weekly limits. All Agents SDK usage will drain your 5h limits faster than using Claude Code directly.” That confirmation comes from Theo’s own testing, not from Anthropic. He says he has reported it to Anthropic.

His tracking issue, pingdotgg/t3code#24649, gives his A/B numbers on one Max account: the interactive app used 7% of the 5-hour window per run, T3 Code 13% and 16%, and claude -p 9%, while the weekly meter moved 2% in every run. He puts the gap at about 1.6x to 1.7x for the same tokens, and says T3 Code doesn’t send more tokens or break the prompt cache. These are one person’s tests on one account, not Anthropic’s figures, and the size of the gap varies between reports.

What Anthropic has said so far

As of 31 Oct 2026, we found no Anthropic statement that confirms, explains or denies the gap, and no fix date. The Claude status page lists no incident about usage limits or the Agent SDK among the incidents it shows for 18 to 30 Oct, so “not confirmed” still applies.

The closest thing is a general review. On 28 Oct 2026, Boris Cherny, whose X profile reads “Claude @anthropicai”, replied on X in a thread about Claude Code usage. He wrote that Anthropic went through the session IDs users shared, “found a few smaller things along the way that made some sessions burn through tokens faster than they should have”, and was “rolling out fixes to those right now”. He also wrote: “We didn’t find a single root cause or any regression in Claude Code.” In most cases, he said, faster usage was traced to “one or two heavy sessions (xhigh effort, /goal, Workflows, Agent Teams, long SDK jobs)”, and he asked people who still see a problem to send /feedback. His reply doesn’t mention #97074, the sdk-cli and sdk-ts labels, or the difference between headless and interactive use, and it doesn’t say whether Agent SDK usage is counted at a different rate. It’s a general review, so we can’t read it as an answer to this report in either direction.

Separately, on 30 Oct 2026 the Claude account on X announced that Max 5x is now Max and Max 20x is now Ultra, and that Anthropic is “removing the 5-hour limit for verified Ultra accounts, starting today with most existing subscribers”. Newer accounts keep a temporary limit until they’re verified, and weekly limits are unchanged. That doesn’t address the label gap. Anthropic says verified Ultra accounts will no longer have a 5-hour limit once it’s removed, and that the “Max 20x” accounts in the older #97074 comments are now called Ultra.

Why the Agent SDK uses your plan at all

Anthropic’s help article on using the Claude Agent SDK with your Claude plan says that “Claude Agent SDK, claude -p, and third-party app usage still draw from your subscription limits”. The same article’s 7 October 2026 update says Max, Ultra and Team plans now include monthly API credits, which cover the Claude Agent SDK and claude -p “when you run them with an API key from your linked Claude Console organization”, and that “when you’re signed in with your Claude plan, the Claude Agent SDK and claude -p still draw from your subscription limits”. The article doesn’t say that plan-signed-in usage is counted at a different rate, which is what the reports ask Anthropic to clarify. Anthropic edits this article, so check its current text.

Step 1: check your real usage

Run /usage in Claude Code to see where your 5-hour and weekly limits stand. If you want it on screen all the time, the Claude Code status line docs list rate_limits.five_hour.used_percentage and rate_limits.seven_day.used_percentage among the data passed to your status line script. The docs say rate_limits appears only for claude.ai Pro, Max and Ultra subscribers (or behind a gateway with spend limits), and only after the first response in a session.

Step 2: move heavy work to the interactive app

In every public A/B test we found, the interactive Claude Code app used less of the 5-hour window for the same work than T3 Code, Agent SDK apps or claude -p. Until Anthropic responds, the practical option is to run long or heavy sessions in the interactive app and keep SDK-based tools for lighter jobs. This is a workaround based on user tests, not an official recommendation, and it may stop mattering if Anthropic changes how usage is counted.

Step 3: use your plan API credits for headless jobs

Anthropic’s help article on monthly API credits for Max, Ultra and Team plans describes credits that are separate from your plan’s usage limits and cover the Claude Agent SDK and claude -p when you run them with an API key from your linked Claude Console organization. Read the article for the amounts, how you claim them and what happens when they run out. If a job you run headless is the one draining your window, running it on an API key moves it off the 5-hour window, but it’s metered as API usage, not as plan usage. That is an official route, and it doesn’t settle the question in #97074.

Some commenters on #97074 report an environment-variable workaround; others warn that it may breach Anthropic’s terms and put the account at risk, and Anthropic hasn’t said whether it’s allowed. We haven’t tested it and don’t recommend it.

Step 4: don’t confuse it with a separate limit report

A different open report, anthropics/claude-code#104738, says an Agent SDK process was rejected with “You’ve hit your session limit” while the Claude desktop app on the same account showed the 5-hour limit at 62%. That’s one user, and it’s a different symptom: two surfaces disagreeing about the limit, rather than one draining faster.

Step 5: add your data to the issue

If you can measure the gap, add your plan, model, Claude Code version and before-and-after 5-hour percentages to #97074. A +1 reaction helps more than a “same here” comment. If your weekly limit is what runs out, see Claude weekly limit reached.
