ChatGPT Pro 200 Codex limits: the 29 Oct cut was canceled

OpenAI has canceled the planned cut to the ChatGPT Pro 200 Codex allowance. If you read that Pro 200 limits drop after 29 October, including in the first version of this post, that’s out of date: on 29 October 2026 OpenAI said it won’t reduce them, and the price stays $200 a month. This post sets out what OpenAI’s pages say now, and then covers the documented ways to make your Codex usage last, whichever plan you’re on: picking the right model and speed, keeping context small, and moving heavy repeat work to the API with a spend cap.

If you want the next step, read Prompt caching not working? Check it in OpenAI and Anthropic (Next.js).

Everything below comes from OpenAI’s help centre, Codex docs and an OpenAI staff post on X, checked on 31 October 2026. Plans and limits change often, so check the pages linked here before you make a decision. We aren’t affiliated with or endorsed by OpenAI; ChatGPT and Codex are OpenAI’s trademarks, used here only to name its products.

What changed, and who it affects

On 29 October 2026, Tibo, whose X profile reads “Codex & ChatGPT @OpenAI”, posted: “We are doubling all usage limits for all Pro 100/200/500 tiers and Business Premium, effective today.” He added: “We heard your kind feedback and won’t be reducing usage limits for Pro 200, so your Work and Codex usage will stay the same.”

The About ChatGPT Pro tiers help page gives the detail:

  • There are three Pro plans: Pro 100 ($100 a month), Pro 200 ($200) and Pro 500 ($500). “Pro 200 includes more usage than Pro 100. Pro 500 offers the highest included usage of the three plans.” Pro 500 is the only one with Ultrafast.
  • The Pro 200 reduction is canceled. “The reduction announced in our September 29 email is canceled. If you already had the higher Work and Codex allowance, you keep it. If you had the lower allowance, it has doubled to match. Your subscription price stays at $200/month.”
  • Pro 100 and Pro 500 get more. “Pro 100 and Pro 500 now include twice their previous Work and Codex allowance. On Pro 200, only the lower allowance doubled.” Existing subscribers receive it automatically, and Plus usage is unchanged.
  • Pro 200 is on sale again. “New Pro 200 subscriptions are available from the pricing page and include the increased Work and Codex allowance. The monthly price remains $200.”
  • More allowance isn’t a promise of more finished tasks. The page says “The amount of work you can complete still depends on the model, task, and settings. A larger allowance does not guarantee twice as many completed tasks.”

So the plans haven’t all changed in the same way. If you were on Pro 200 with the higher allowance, you keep it. If you were on the lower one, it doubled to match. Pro 100 and Pro 500 doubled. The weekly GPT-6 Pro message limit in Chat is a separate meter from your Work and Codex allowance. OpenAI’s help pages don’t publish a multiplier or a message count for Pro, so the safest figure is the one on your own usage dashboard.

The first version of this post quoted a Hacker News post about a cut from 20 times to 10 times the ChatGPT Plus allowance. That cut is the one OpenAI has now canceled, so we’ve removed it.

What uses up your allowance

The same help page says: “Usage depends on the model, the amount of context processed, reasoning, tool use, information retrieval, caching, and speed mode.” The Codex pricing page adds that “larger projects, long-running tasks, or extended sessions that require the agent to hold more context will use significantly more per message”, and that “prompt length alone isn’t a reliable estimate”.

It also says local messages and cloud chats share one allowance, and “Cloud tasks may use more of your allowance than local messages.” ChatGPT Work and Codex share usage too, so a long Work session draws on the same allowance as your coding.

Each of the habits below works on one of those factors.

1. Check where you stand first

The Codex pricing page points to a usage dashboard for current limits and reset times. In the Codex CLI, the slash command docs describe /usage as “View account token usage or use a rate-limit reset” and /status as “Display session configuration and token usage”. The pricing page also says you can use /status to see your remaining limits during a session, so if one command doesn’t show what you need, try the other. OpenAI suggests checking the dashboard “every week or two to understand your pace and remaining capacity.”

Check it now, and again after a normal working week. Then you’ll know your own pace from your own numbers, instead of guessing from a multiplier.

2. Turn off Fast mode unless you need it

Speed mode is the factor with the clearest numbers. From the help page: “Compared with Standard mode for the same model, Fast mode uses your included allowance at 2.5 times the rate, and Ultrafast for GPT-6 Astra and GPT-6.1 Sol uses it at 8 times the rate.” Ultrafast is only on Pro 500, so on Pro 200 the one to watch is Fast. On Pro 500, the same page says Ultrafast uses your included usage first at 8 times the Standard rate, then draws from your credit balance at 6 times the Standard credit rate.

The Speed docs say /fast toggles it in the CLI, and /statusline can show it in the footer so you notice when it’s on. If you’ve set it as your default in config.toml, remove service_tier = "fast" there. At 2.5 times the rate, the same work in Fast mode takes 2.5 times as much allowance as it would in Standard.

3. Match the model and reasoning effort to the task

The Models page says “Astra suits the most demanding workflows”, that “GPT-6.1 Sol offers near-Astra performance at a lower cost than Astra”, and that “Luna suits focused, repeatable tasks.” On reasoning effort, it says higher effort “can improve results for complex tasks, but it takes longer and uses more tokens. Start with the default effort and increase it when the task needs deeper planning or analysis.”

Codex’s pricing table shows how wide the gap is. For Plus, it estimates 5–45 local messages per five hours with GPT-6 Astra, 15–160 with GPT-6.1 Sol and 350–3,000 with GPT-6 Luna. Those are Plus estimates, not Pro figures, and OpenAI says “These estimates are not fixed message limits”. The ratio is still a useful guide.

You can switch per session with /model, or set a lighter default in ~/.codex/config.toml and move up only when you need to:

# ~/.codex/config.toml
model = "gpt-6-luna"
model_reasoning_effort = "high"

Both keys are in the Codex config reference. The available models and effort levels depend on your plan and client, so check /model to see what you can pick. The Models page says “Start with High for Luna”, so the example uses high.

4. Keep context small

Context is the factor that’s easiest to let grow without noticing. The pricing page lists tips for making limits last longer:

  • “Control the size of your prompts. Be precise with the instructions you give the agent, but remove unnecessary context.”
  • “Limit source material. Provide only relevant files and, when possible, narrow the sources or date range.”
  • “Match the output to the need. Define the audience, format, and length, and separate required work from optional improvements.”
  • Reduce the size of your AGENTS.md, for example by nesting files within the repository.
  • “Limit the number of MCP servers you use. Every MCP server adds more context to your messages and uses more of your limit.”

Two CLI commands help with long sessions. According to the slash command docs, /compact “replaces earlier turns with a concise summary, freeing context while keeping critical details”, and /new starts a fresh chat in the same CLI session. If a thread has drifted onto a different task, a new chat avoids carrying the old context into every message.

On AGENTS.md: the AGENTS.md guide explains that Codex reads the files from the project root down to your working directory and joins them, up to project_doc_max_bytes (32 KiB by default). Every message pays for that text, so keep the root file short and put team- or folder-specific rules in nested files, where they only load when you work in that part of the repo.

5. Plan around the reset, not against it

The pricing page says that if you reach your limit during an active turn, “the agent will be able to continue working on that turn, subject to fair use limits.” It also notes that Pro plans “currently have no five-hour limit”, though weekly limits may apply. OpenAI’s Managing usage help article says the same for Pro 100, Pro 200 and Pro 500, and adds that your plan still has an included usage allowance.

In practice, start big tasks when you have room, not when the dashboard is nearly empty. Batch related changes into one well-scoped task rather than many small back-and-forth turns, each of which resends context. That last point is our inference from the “context” factor above, not a figure OpenAI publishes.

6. Move heavy repeat work to the API, with a cap

Some work doesn’t need a subscription allowance at all: a nightly job that summarises logs, a CI step that writes release notes, or a batch of files to classify. OpenAI documents three routes:

  • Codex with an API key. The auth docs say Codex can sign in with an API key, and that “OpenAI bills API key usage through your OpenAI Platform account at standard API rates.” The pricing page confirms that “All users may also run extra local chats using an API key”. Cloud features such as GitHub code review aren’t available this way.
  • Non-interactive runs. The non-interactive mode guide uses codex exec for “CI, pre-merge checks, scheduled jobs”.
  • The Batch API, for work that doesn’t need Codex. If the job is plain model calls, the Batch guide offers “50% lower costs” with “a clear 24-hour turnaround time”, for jobs that don’t need an immediate answer.

A scheduled job with an API key might look like this. The commands are from the auth and non-interactive docs:

# On a machine you control: sign Codex in with an API key (billed at API rates)
printenv OPENAI_API_KEY | codex login --with-api-key

# In a scheduled job or CI step
codex exec "generate release notes for the last 10 commits" | tee release-notes.md

In CI, don’t expose the key to the whole job. OpenAI’s non-interactive guide suggests the Codex GitHub Action on GitHub, or setting CODEX_API_KEY only on the codex exec step.

Moving work to the API swaps a fixed allowance for a bill with no ceiling, unless you set one. Do that first:

  • Use a separate project and key for the job, and set a monthly hard limit on that project. The spend limits guide says requests then fail with a 429 and project_spend_limit_exceeded, and warns that “Enforcement is not instantaneous, so recorded spend can slightly exceed the configured amount.”
  • Add spend alerts below the hard limit, so you hear about a runaway job before it stops.
  • Keep the stable part of the prompt at the start. The prompt caching guide says caching is on by default for supported models and reuses a matching prefix, “the unchanged tokens at the beginning of a prompt”. Cached input is billed at a lower rate on most models; see the API pricing page.

Check API pricing for the model you plan to use before you move anything. Whether the API works out cheaper than staying within the subscription depends on your volume and model, and we haven’t compared them for any specific workload.

Checklist

  • Look at your usage dashboard now, and again after a normal working week.
  • Turn Fast mode off by default, and use it only when speed matters.
  • Default to a lighter model and effort, and move up per task.
  • Trim AGENTS.md and disable MCP servers you aren’t using.
  • Use /compact or /new when a session gets long or changes topic.
  • Move scheduled and CI work to an API key on a separate project with a hard spend limit.
