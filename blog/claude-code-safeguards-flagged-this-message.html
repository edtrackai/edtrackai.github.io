Claude Code “safeguards flagged this message”: what to do

As of 24 October 2026. Anthropic may change this behavior at any time, so check the linked issues and help pages before you follow any step.

If you want the next step, read Claude weekly limit reached? Why it burns fast + what to do.

If Claude Code stops with this message, you're not alone:

API Error: Sonnet 5.5's safeguards flagged this message (https://www.anthropic.com/legal/aup). This sometimes happens with safe, normal conversations. Claude Code can't respond to this message with Sonnet 5.5.

That's the exact text quoted in anthropics/claude-code #101076 (opened 10 Oct 2026), after the reporter asked a plain question about a missing skill. In #104364 (opened 22 Oct 2026), another user reports "Opus 5.5's safeguards flagged this message" during "an ordinary development request".

This isn't a usage limit. The message says Anthropic's safeguards flagged that one message.

What to try first: retry, edit, or start a fresh session

The error in #101076 suggests its own next steps: "Double press esc to edit your last message, or try a different model with /model."

  1. Retry, or edit your last message if it didn't say clearly what you want done in the code. The error itself says this "sometimes happens with safe, normal conversations". Don't reword a request just to get it past the safeguards.
  2. Start a fresh session if the problem seems to come from earlier context. Users report this can help, though Anthropic hasn't documented it.

What the message means

The error links Anthropic's Usage Policy. Anthropic's help article Our Approach to User Safety describes "Detection models that flag potentially harmful content based on our Usage Policy" and "Safety filters on prompts, which may block responses from the model when our detection models flag content as harmful." It adds: "These features are not failsafe, and we may make mistakes through false positives or false negatives."

The [reasoning_extraction] variant

Some messages add Details: [reasoning_extraction]. We didn't find an Anthropic page that explains this label as of 24 October 2026, so we won't guess how it works. The reporter in #104364 writes: "I wasn't asking the model to reveal its reasoning, thinking, or system prompt". They point to the workspace context Claude Code sessions carry "(CLAUDE.md, skills, memory)".

Switch model for that message

The error says Claude Code can't respond "with Sonnet 5.5", and suggests trying "a different model with /model". Another model may answer the same normal request, but that isn't guaranteed: #104364 reports the error on Opus 5.5 too.

Check your CLAUDE.md, hooks, and pasted content

Claude Code sends more than your last line. Your CLAUDE.md, skills, memory, and anything pasted earlier go along with it. If the error keeps coming back in one project, mention that in your /feedback report, since Anthropic hasn't said which context is checked. Keep the content honest and on task. The aim is to describe your real request clearly, not to get around the safeguards.

Report a false positive

The error in #101076 says: "Send feedback with /feedback or learn more: https://support.claude.com/en/articles/8106465". If you think the block was a mistake, use /feedback in Claude Code and include the request ID if you have one. You can also add details to the GitHub issues above. Anthropic's help article says it encourages feedback on these safety measures.

Don't try to evade or work around the safeguards. That goes against Anthropic's Usage Policy and could put your account at risk.

It isn’t a usage limit

If Claude Code stopped because you ran out of allowance, that's a different message. See Claude weekly limit reached and how to reduce Claude Code token usage.

FAQ

Does it count against my limit? We found no official answer as of 24 October 2026.

Is my account at risk? Anthropic's help article says it "may temporarily apply enhanced safety filters to users who repeatedly violate our policies". It doesn't say a single false positive affects your account. Reporting false positives helps Anthropic tell them apart.

Why does it flag normal code? Anthropic says its detection models can make mistakes "through false positives or false negatives". It hasn't said why particular requests are flagged.

What is reasoning_extraction? A label shown in the error details. We didn't find an Anthropic page that explains it as of 24 October 2026.

Will switching to Opus help? It may, since the error says Claude Code can't respond with Sonnet 5.5 specifically. #104364 shows Opus 5.5 can flag messages too.

How do I report it? Use /feedback in Claude Code, as the error suggests.
