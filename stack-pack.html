Cursor rules for Drizzle, Better Auth, Next.js, and Polar

Six rule files in .cursor/rules/. Two always apply (project and security), and the other four attach by file path. Some of what they tell the agent:

  • Drizzle (20-drizzle.mdc). Designed to have your agent change the schema, run drizzle-kit generate, and commit the SQL and drizzle/meta/. It tells the agent to use drizzle-kit push only on a throwaway local database and never with --force, to include the owner or org in every select, update, or delete on user data, and to import db only on the server.
  • Better Auth (30-better-auth.mdc). Tells your agent to read the secret and base URL from env and fail fast if either is missing, use the Drizzle adapter with provider: "pg", build trusted origins from env with no bare "*", and keep nextCookies() last. It instructs the agent to check sessions on the server with auth.api.getSession and organization permissions with auth.api.hasPermission.
  • Next.js 16 (10-nextjs.mdc). Reminds your agent that params and searchParams are Promises, and that every Server Action is a public POST endpoint, so each action should check the user first. It tells the agent to keep proxy.ts to optimistic redirects and never match /api/auth or webhook paths.
  • Polar (40-polar.mdc). Tells your agent to configure the Better Auth Polar plugin so the Polar customer's external_id is your user id, verify webhooks on the raw body, dedupe on webhook-id, and grant access from the entitlement row, never from the checkout success redirect.

How it works

  1. Install. Copy everything in pack/ into your repo root, including the dot-folders. If you already have .claude/settings.json, merge it by hand. Or install the Claude Code plugin:
    /plugin marketplace add ./path/to/plugin
/plugin install stack-pack@stack-pack-local
    For Cursor, copy plugin/stack-pack-cursor to ~/.cursor/plugins/local/stack-pack, reload the window, and copy pack/AGENTS.md and pack/scripts/ into your repo.
  2. List env names, not values. .env.example holds the names (DATABASE_URL, BETTER_AUTH_SECRET, POLAR_ACCESS_TOKEN, and the rest); real values stay in .env.local.
  3. Run the launch check.
    node scripts/launch-check.mjs
    Fix HIGH findings first. --strict fails on MEDIUM too, and --json gives machine output for CI.
  4. Work as usual. In Claude Code, ask for "a projects table owned by the user" and the add-drizzle-table skill loads. In Cursor, the rules attach by file path.
  5. Keep agents in sync. After you edit AGENTS.md, run node scripts/sync-agents.mjs (add --check in CI).

What this doesn’t do

  • The guard reads commands, not your environment. A push whose database URL comes from .env isn't detected, and neither are aliases or functions, scripts in files (sh deploy.sh, make) or commands built at run time; the docs list the limits.
  • The launch check is pattern matching, so it can miss issues. A clean run doesn't mean an app is secure.
  • Not tested in a live Claude Code or Cursor session, against a live Polar account or against a hosted database, or running the reference wiring as a server.
  • The hooks are for Claude Code. Cursor, Codex, and Copilot get the rules and skills.
  • The checks are for Postgres only, and there are no Stripe-specific rules or checks.

Requirements

Needs Node 24 or later. As of 23 Oct 2026, @polar-sh/better-auth 2.1.0 and @polar-sh/nextjs 1.1.0 declare Node 24+ (the Better Auth CLI, npx auth@latest, declares Node 22.12+), so the reference app and any app on this stack need Node 24+. The pack's own rules, hooks and scripts have no dependencies; its full test run passed on Node 24.22. The guard is designed to fail closed (deny the action) if it crashes or times out, on Claude Code 2.1.295 or later. On earlier versions, a hook that times out or can't start lets the action run (as of 23 Oct 2026, Claude Code's npm stable and latest channels are 2.1.308 and 2.1.309). The checks are for Postgres only.

FAQ

Is this a starter app?
No. It's a rules pack: rules, skills, hooks, and a launch-check script that you add to your own app. fixtures/good-app is reference wiring that the checks and tests run against, not a starter kit.
Which AI coding tools does it work with?
Claude Code reads CLAUDE.md and gets the skills and the 3 hooks. Cursor gets 6 rules and the skills, as copy-in files or a Cursor plugin. Codex and the GitHub Copilot coding agent read AGENTS.md, and a generated .github/copilot-instructions.md is included. The hooks are for Claude Code only.
Which Node version do I need?
Node 24 or later. As of 23 Oct 2026, @polar-sh/better-auth 2.1.0 and @polar-sh/nextjs 1.1.0 declare Node 24+, so any app on this stack needs Node 24+. The pack's own hooks and scripts have no dependencies.
Will the guard stop every push to my production database?
No. It's designed to deny drizzle-kit push --force and pushes or migrations aimed at a non-local database URL on the command line. It reads commands, not your environment, so a plain push whose database URL comes from .env isn't detected. The rules also tell the agent not to push to shared databases, and the launch check flags drizzle-kit push in build scripts.
If the launch check comes back clean, is my app secure?
Not necessarily. It runs 20 pattern checks offline, so it can miss issues. A clean run doesn't mean an app is secure. Treat it as a pre-launch list, not an audit.
Has it been tested against a live Polar account?
No. It hasn't been tested in a live Claude Code or Cursor session, against a live Polar account or a hosted database, or with the reference wiring running as a server. Polar webhook signatures are checked in tests with the official @polar-sh/sdk.
Does it cover the Better Auth Polar plugin and Polar webhooks?
Yes, as two separate pieces. The Polar Cursor rule and the polar-checkout-access skill are designed to have your agent set up the Better Auth Polar plugin (@polar-sh/better-auth) for checkout and the customer portal, with createCustomerOnSignUp so the Polar customer's external_id is your user id. For webhooks, they point the agent to a separate route, app/api/webhooks/polar/route.ts, rather than the Better Auth plugin. The polar-webhooks skill is designed to have your agent read the raw body and verify it with validateEvent from @polar-sh/sdk, or with the Webhooks() adapter from @polar-sh/nextjs. It also tells the agent to return 403 on a bad signature, dedupe on webhook-id, and upsert access rows. The pack doesn't cover configuring webhooks through the Better Auth plugin itself.
